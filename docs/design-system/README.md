# Design System — شعله

مرجع نهایی طراحی این محصول. هر صفحه‌ی جدید، هر کامپوننت جدید و هر تصمیم بصری
باید از همین‌جا بیرون بیاید.

> **قانون حاکم:** اگر یک طراحی جدید با این سند در تضاد بود، اول در سطح *سیستم*
> تصمیم گرفته می‌شود — یا سیستم عمداً تغییر می‌کند و این سند به‌روز می‌شود، یا
> طراحی تغییر می‌کند. هیچ صفحه‌ای مستقل و بی‌قاعده طراحی نمی‌شود.

---

## اصل مرکزی

> **محصول، آدم‌ها هستند. رابط باید ساکت بماند تا آدم‌ها دیده شوند.**

این محصول وقت و توجه یک انسان را می‌فروشد. پس گرمی و رنگِ صفحه باید از عکس و
محتوای کاربرها بیاید، نه از تزئینات رابط. هر افکتی که با محتوا رقابت کند، حذف
می‌شود.

## پنج اصل عملی

1. **سلسله‌مراتب از فضا و تایپوگرافی می‌آید، نه از افکت.**
   ترتیب استفاده: جایگاه و گروه‌بندی ← فضا ← مقیاس و وزن فونت ← کنتراست متن ←
   سطح ← مرز ← سایه. اگر برای مهم نشان دادن چیزی به سایه رسیدی، یعنی مرحله‌ی
   اول را درست انجام نداده‌ای.

2. **رنگ اشباع فقط سه جا ظاهر می‌شود:** اکشن اصلی، وضعیت (زنده/موفق/خطا)، و
   نشان «تازه». بقیه‌ی رابط خنثی است.

3. **مقیاس، نه مقدار دلخواه.** هر عدد (فاصله، اندازه‌ی فونت، شعاع) باید از
   مقیاس مستند بیاید. اگر لایه‌ای «۱۴ پیکسل لازم دارد»، آن لایه اشتباه است.

4. **اکشن اصلی همیشه در دسترس شست است** — پایین صفحه، ثابت. بالای صفحه فقط برای
   جهت‌یابی است (کجا هستم، چطور برگردم).

5. **یک هویت، دو سطح.** تیره و روشن دو تم متفاوت نیستند؛ یک هویت‌اند در دو
   محیط. نام توکن‌ها یکی است، فقط مقدارشان عوض می‌شود.

فقط به‌عنوان یک خط توضیحی کنارش می‌آید تا کاربر ارزش واقعی را بفهمد، و هیچ‌وقت
جای دراپ را نمی‌گیرد.

| فایل | محتوا |
|---|---|
| `01-foundations.md` | رنگ، تایپوگرافی، فاصله، شعاع، ارتفاع، حرکت، آیکون |
| `02-components.md` | دکمه، ورودی، لیست/کارت، هدر، ناوبری پایین، شیت، بج/چیپ، حالت‌ها |

در کد:

```
frontend/src/styles/
├── tokens.css        ← فقط توکن (پایه + معنایی + تیره/روشن)
├── base.css          ← ریست، تایپوگرافی پایه، فونت
└── components/*.css  ← هر کامپوننت، فقط با توکن معنایی
```

## چطور از این سیستم استفاده کنیم

**ساخت یک صفحه‌ی جدید:**

1. الگوی هدر را از `02-components.md` بردار — یک الگو بیشتر وجود ندارد.
2. محتوا را به‌صورت سکشن و لیست بچین، نه کارت‌های شناور.
3. اکشن اصلی را پایین صفحه ثابت کن.
4. هر عددی که می‌نویسی باید یک توکن باشد. اگر توکن نداشت، اول اینجا اضافه‌اش کن.
5. چهار حالت را تعریف کن: بارگذاری، خالی، خطا، موفق. بدون این‌ها صفحه ناتمام است.
6. قبل از تمام کردن، `04-anti-patterns.md` را یک بار مرور کن.

**اضافه کردن یک توکن جدید:** باید بتوانی در یک جمله بگویی این توکن چه *معنایی*
را بیان می‌کند که توکن‌های موجود نمی‌کنند. اگر نتوانستی، توکن لازم نیست.

**اضافه کردن یک واریانت جدید به کامپوننت:** باید کاری داشته باشد که واریانت‌های
موجود ندارند. واریانتِ بدون کارِ مشخص، حذف می‌شود.
