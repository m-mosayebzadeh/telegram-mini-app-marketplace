# موارد ممنوع

این فایل به‌اندازه‌ی بقیه‌ی سیستم مهم است. سیستمی که فقط «بله» می‌گوید، زیر
فشار هیچ راهنمایی نمی‌دهد.

هر مورد زیر یک بار در نسخه‌ی قبلی این محصول اتفاق افتاده است. اعداد از همان
ممیزی می‌آیند (`docs/UI_REDESIGN_ANALYSIS.md`).

---

## ممنوع — بصری

| مورد | چرا |
|---|---|
| **گرادیانت روی سطح یا دکمه** | تزئین جای سلسله‌مراتب را می‌گیرد. نسخه‌ی قبلی ۱۹ مورد داشت |
| **گلس‌مورفیسم** (شفافیت + بلور) به‌عنوان سطح | ۲۵ مورد در نسخه‌ی قبلی. سطح باید مات باشد |
| **سایه‌ی رنگی یا glow** | سایه ارتفاع را نشان می‌دهد، نه اهمیت را |
| **سایه‌ی پیش‌فرض روی کارت** | پیش‌فرض بدون سایه است |
| **بیش از یک رنگ شاخص** | دو شاخص یعنی هیچ‌کدام شاخص نیستند |
| **رنگ به‌عنوان تنها حامل معنا** | همیشه با آیکون، متن یا وزن همراه شود |
| **قرص‌کردن همه‌چیز** | وقتی شعاع همه‌جا یکسان است، دیگر اطلاعاتی منتقل نمی‌کند |
| **ایموجی به‌جای آیکون** | آیکون خطی با ضخامت ثابت، همیشه |
| **پس‌زمینه‌ی تزئینی** (لکه‌ی نورانی، بلاب) | با محتوا رقابت می‌کند |
| **متن وسط‌چین در لیست** | لیست از لبه‌ی `start` شروع می‌شود |

**تنها گرادیانت مجاز:** اسکریم تیره روی عکس، برای خوانا شدن متنِ رویش. این
کارکردی است، نه تزئینی.

## ممنوع — سیستمی

| مورد | چرا |
|---|---|
| **مقدار خارج از مقیاس** | نسخه‌ی قبلی ۱۷ شعاع و ۲۰ اندازه‌ی فونت داشت |
| **اندازه‌ی فونت نیم‌پیکسلی** | نشانه‌ی قطعی نبودن مقیاس |
| **استایل inline برای چیزی که سیستم باید داشته باشد** | ۷۴ مورد در نسخه‌ی قبلی؛ هر کدام یک سوراخ در سیستم |
| **رنگ خام (hex) داخل کامپوننت** | فقط توکن معنایی |
| **خواندن توکن پایه از داخل کامپوننت** | فقط لایه‌ی معنایی |
| **دو سیستم طراحی موازی** | نسخه‌ی قبلی هم‌زمان کیت تلگرام و `hp-*` داشت و با خودش می‌جنگید |
| **الگوی هدر دوم** | نسخه‌ی قبلی ۴ الگو داشت و ۴ صفحه بدون هدر |
| **کارت داخل کارت** | اگر لازم شد، بیرونی باید سکشن می‌بود |
| **چند تم رنگی هم‌زمان** | سه تمِ متفاوت یعنی هیچ هویت بصری |

## ممنوع — تجربه‌ی کاربری

| مورد | چرا |
|---|---|
| **هدف لمسی زیر ۴۴ پیکسل** | نسخه‌ی قبلی دکمه‌های ۳۱ و ۳۴ پیکسلی داشت |
| **اکشن اصلی بالای صفحه** | خارج از دسترس شست |
| **اسپینر تمام‌صفحه** | زمینه را از بین می‌برد؛ اسکلت در جای محتوا |
| **حالت خالی بدون راه رو به جلو** | «چیزی نیست» یک بن‌بست است |
| **خطا بدون تلاش دوباره** | کاربر را بدون گزینه رها می‌کند |
| **از دست رفتن موقعیت اسکرول در بازگشت** | جای کاربر را گم می‌کند |
| **دیالوگ برای اطلاع‌رسانی** | دیالوگ فقط برای تصمیم با عواقب |
| **اکشن مخرب در مسیر طبیعی شست** | لمس تصادفی |
| **اتکا به hover** | روی موبایل وجود ندارد |
| **نوار وضعیت یا کیبورد جعلی** | روی گوشی واقعی دوبار رندر می‌شود |
| **وابستگی به ژست بازگشت پلتفرم** | هر صفحه باید بازگشت دیداری داشته باشد |

## ممنوع — محتوا

- **داده‌ی جعلی در محصول واقعی.** هیچ کارتِ نمایشی، هیچ عدد ساختگی، هیچ فیچر
  تزئینی که به بک‌اند وصل نیست.
- **عدد و آیکونِ بی‌کارکرد** فقط برای پر کردن فضا.
- **متن پرکننده.** اگر سکشنی خالی به نظر می‌رسد، مشکل از چیدمان است نه از کمبود
  متن.

## تست نهایی قبل از ship

برای هر افکت بصری روی صفحه بپرس: **اگر این را حذف کنم، چه چیزی از دست می‌رود؟**

اگر جواب «هیچی» یا «ساده‌تر می‌شود» است، حذفش کن. ساده‌تر، پیش‌فرضِ درست است؛
افکت باید کارش را ثابت کند.
