# مشخصات طراحی — Modern Monochrome Social

این سند سیستم طراحی بصری معرفی‌شده در برنچ `modern-design-specification` را توصیف می‌کند: یک بازطراحیِ کاملاً بصری روی معماری و منطق موجود اپلیکیشن (بدون تغییر در بک‌اند، API، مسیرها، یا منطق کسب‌وکار).

جهت طراحی مرجع: [این شات دریبل](https://dribbble.com/shots/26938330-Social-App-UI-Clean-UI-Concept) — فقط برای حس بصری (سادگی، فاصله‌گذاری، سلسله‌مراتب تایپوگرافی، آرامش بصری)، نه کپی رنگ/لایوت/برندینگ. الهامات دیگر: اینستاگرام، تلگرام، اپ‌های مدرن iOS.

اصل بنیادین طراحی:

> **رابط کاربری ساکت است. محتوا رنگ را فراهم می‌کند.**

---

## ۱. فلسفه طراحی

- مونوکروم، مینیمال، آرام، بالغ، تولیدی/production-ready
- بازطراحی **با حذف پیچیدگیِ بصریِ غیرضروری**، نه با افزودن جلوه — هر جا شک بود، ساده‌تر انتخاب شد
- بدون گرادیانت دائمی، بدون glassmorphism به‌عنوان سبک اصلی، بدون glow/سایه‌ی رنگی، بدون رنگِ لهجه‌ی ثابت (بنفش/نارنجی/صورتی/آبی/سبز/زرد)
- رنگ‌های معنایی (success/warning/danger) فقط جایی مجازند که واقعاً لازم است (وضعیت تراکنش، خطا، حذف) و همیشه محدود/کم‌رنگ باقی می‌مانند

## ۲. سیستم توکن‌ها (Design Tokens)

همه‌ی توکن‌ها در `frontend/src/styles/theme.css` به‌صورت CSS custom properties تعریف شده‌اند: مقدارهای پیش‌فرض روی `:root` (تم روشن) و بازتعریف کامل روی `[data-theme='dark']` (تم تیره) — با **نام توکنِ یکسان**، فقط مقدار فرق می‌کند. هیچ کامپوننتی رنگ هاردکد ندارد؛ همه از این توکن‌ها می‌خوانند.

### سازگاری با کد قبلی — الگوی alias

اپ قبلاً یک سیستم توکنِ `--hp-*` («Velvet After Dark»: بنفش/گلبهی/کهربایی، سه پالتِ قابل‌سوییچ) داشت که در **صدها** خط از `theme.css` مصرف می‌شد. به‌جای بازنویسیِ تک‌تکِ آن مصرف‌کننده‌ها، توکن‌های قدیمی به توکن‌های معنایی جدید alias شدند (مثلاً `--hp-bg: var(--color-background)`، `--hp-grad: var(--color-action)`، `--hp-glow: none`). نتیجه: کلاس‌های موجود (`.hp-card`, `.hp-btn`, `.hp-list-row`, …) دقیقاً همان‌طور کار می‌کنند، ولی چیزی که رسم می‌کنند از سیستم جدید می‌آید — یعنی مهاجرتِ بصریِ کل اپ بدون دست‌زدن به هر صفحه، فقط با تغییر یک فایل CSS. جاهایی که رنگ به‌صورت هاردکد بود (نه از طریق توکن) تک‌تک پیدا و به توکن معنایی مناسب تبدیل شدند (رجوع کنید به بخش ۸).

## ۳. تم روشن/تیره

- کلید سوییچ: `document.documentElement.dataset.theme = 'light' | 'dark'` — نه `document.body`، تا هرچیزی خارج از یک صفحه‌ی خاص هم (شیت، مودال، توست) پوشش داده شود.
- منبع state: `frontend/src/lib/ThemeContext.tsx` (`useHpTheme()`).
- پایداری: `localStorage` (کلید `hp-theme-mode`) — همان الگوی ساده‌ای که پروژه از قبل برای تم رنگی و زبان استفاده می‌کرد؛ وابستگیِ جدیدی اضافه نشد.
- پیش‌فرض وقتی چیزی ذخیره نشده: ترجیح سیستم‌عامل/تلگرام (`prefers-color-scheme`) — نه یک مقدار ثابت — تا کسی که همه‌جا تم تیره دارد مجبور به انتخاب دستی نباشد؛ به‌محض انتخاب صریح، آن انتخاب همیشه برنده است.
- محل سوییچر: داخل تب پروفایل ← بخش تنظیمات، دقیقاً همان جایی که سوییچر رنگیِ قبلی بود (`components/ThemeSwitcher.tsx`) — مکان جدیدی در ناوبری ساخته نشد.
- این جایگزینِ کاملِ سیستم قبلی «سه پالت رنگی» (velvet/copper/jade) است؛ چون طراحی جدید ذاتاً مونوکروم است، دیگر «پالت» به‌معنای قبلی وجود ندارد — فقط روشن/تیره.

## ۴. تایپوگرافی

فونت: `'Inter', 'Vazirmatn', system-ui, ...` — چیدمانِ عمدی: چون Inter هیچ گلیف فارسی ندارد، مرورگر خودکار برای هر کاراکترِ فارسی به Vazirmatn سقوط می‌کند و برای هر کاراکتر لاتین از Inter استفاده می‌کند؛ یعنی یک stack واحد متن کاملاً فارسی، کاملاً انگلیسی، و ترکیبی (نام+یوزرنیم لاتین) را درست رندر می‌کند. هر دو فونت async لود می‌شوند (`index.html`، همان الگوی preload+swap قبلی) تا شبکه‌ی کند تلگرام رندر اولیه را بلاک نکند.

مقیاس (طبق درخواست، پیاده‌سازی‌شده روی کلاس‌های موجود متن، نه بازسازی کامل):

| نقش | اندازه/وزن |
|---|---|
| Display | 28–32px / 700 |
| Title | 22–24px / 700 |
| Heading | 18–20px / 600 |
| Body | 15–16px / 400 |
| Body Medium | 15–16px / 500 |
| Caption | 12–13px / 400 |

## ۵. اجزای مشترک (Reusable Components)

اپ از قبل یک سیستمِ کلاسِ مشترک در `theme.css` دارد (`.hp-btn`, `.hp-list`/`.hp-list-row`, `.hp-card`, `.hp-field`/Input, `.hp-sheet`, `.hp-badge`, `.hp-empty`, `.hp-avatar-*`, …) که همه‌ی صفحات از آن استفاده می‌کنند — دقیقاً معادل چیزی که «Reusable Components» در این سند می‌خواهد. به‌جای ساختن یک کتابخانه‌ی موازیِ جدید (که ریسک واگرایی و نقض «یک پیاده‌سازیِ کامپوننت، نه یکی برای هر تم» را دارد)، همین سیستم حفظ و بازطراحی شد:

- **دکمه‌ها**: `.hp-btn-gradient`/`.hp-btn-sm-filled` دیگر گرادیانت نیستند — پس‌زمینه‌ی solid `--color-action` + متنِ `--color-action-text`. نام کلاس‌ها برای سازگاری با صدها استفاده‌ی موجود حفظ شد.
- **کارت‌ها/لیست‌ها**: `.hp-card`/`.hp-list` دیگر شیشه‌ای/بلور نیستند — سطح solid `--color-surface-elevated`، حاشیه‌ی ظریف `--color-border`، شعاع ۱۴px (به‌جای ۲۰–۲۴px قبلی).
- **شیت/مودال**: `.hp-sheet` سطح solid با شعاع بالای ۲۰px، بدون بلور پس‌زمینه (خودِ سطح دیگر شفاف نیست که بلور معنا داشته باشد)؛ بک‌دراپ همچنان کمی بلور دارد (اثر تمرکز روی مودال، نه glassmorphism دکوراتیو).
- **بج‌ها**: یک رنگِ notify واحد برای «چیزی جدید است» در کل اپ (نه رنگ‌های مجزا برای هر نوع رویداد).
- **آواتار**: دایره‌ی ساده، حاشیه‌ی موی نازک — بدون رینگ گرادیانتِ رنگی.

## ۶. ناوبری (بدون تغییر در معماری اطلاعات)

### نوار پایین — ۵ آیتم، دست‌نخورده

مسیرها/لیبل‌ها از `frontend/src/App.tsx` عیناً حفظ شدند: **پروفایل، تعاملات، گفتگوها، کشف** (۴ تب همیشگی) + **پنل مدیریت** (تبِ پنجمِ شرطی، فقط برای حساب‌های دارای دسترسی ادمین). فقط ظاهر تغییر کرد: آیکون‌های مونوکروم (از قبل currentColor بودند)، حالتِ فعال با `--color-text-primary` به‌جای بنفشِ برند، بدون رنگ درخشان. بج‌های «چیز جدید» (`.hp-nav-unseen-dot`) هم از رنگ notify واحد استفاده می‌کنند.

### پنل مدیریت — ساختار اطلاعاتیِ موجود، دست‌نخورده

```
پنل مدیریت (/admin)
 └─ مالی (/admin/finance)  — فقط اگر دسترسیِ finance.* داشته باشد
     ├─ شارژها (/admin/topups)     — دسترسی: finance.topups
     └─ کارمزدها (/admin/rates)    — دسترسی: finance.rates
 └─ دسترسی‌ها (/admin/access)      — فقط owner
```

این دقیقاً همان چیزی است که در `backend/app/models/admin_grant.py` و روترهای ادمین پیاده‌سازی شده — چیزی اضافه/حذف نشد. بصری‌سازیِ پنل ادمین از **همان** کلاس‌های مشترک استفاده می‌کند (`.hp-list-row`, `.hp-page-header`, آیکون‌های مونوکروم) — هیچ سیستم بصریِ جداگانه یا ویجت رنگیِ داشبوردی برایش ساخته نشد.

## ۷. صفحه‌به‌صفحه

| صفحه | تغییر اصلی |
|---|---|
| **پروفایل** | بازطراحیِ ساختاری — کاورِ گرادیانتیِ گلوداری + کارتِ شیشه‌ایِ شناور + رینگِ آواتارِ رنگی حذف شدند؛ یک ستونِ ساده و وسط‌چین: آواتار → نام → یوزرنیم → نشان اعتماد/تولد → بیو → موقعیت → علایق → آمار فالوور/فالووینگ → اکشن اصلی → (تب‌های محتوا/پیشنهاد، شبکه‌ی محتوا — بدون تغییر). فاصله‌گذاری و تایپوگرافی جای کارت را می‌گیرند. |
| **کشف/Discover** | همان ترکیب آواتار+نام+یوزرنیم+بیو+محتوا؛ از طریق `.hp-card`/`.hp-list` بازطراحی‌شده به‌صورت خودکار مونوکروم شد. |
| **تعاملات/Activity** | لیست تب‌محورِ موجود حفظ شد؛ بج‌های شمارشی هم‌رنگ (رنگ notify واحد)، بدون کارت‌های رنگی. |
| **گفتگوها/Chats** | هدر و کامپوزر چت (که پیش‌تر پس‌زمینه‌ی تیره‌ی ثابت hardcoded داشتند — یک باگ واقعی در تمِ روشن، چون متن روی متنِ هم‌رنگ می‌افتاد) به سطح `--color-surface-elevated` منتقل شدند؛ ردیف‌های تمیز، جداکننده‌های ظریف. |
| **محتوا/Content** | پوششِ محتوای قفل‌شده از یک گرادیانتِ رنگیِ چندجهته‌ی متحرک (`hp-shimmer`) به یک اورلی خنثیِ ساده + آیکون قفل تبدیل شد — بدون رنگِ تزئینی. |
| **پیشنهادها/Offers** | سلسله‌مراتبِ ساده (عنوان → قیمت → مدت → توضیحات → اکشن) از قبل برقرار بود؛ هیچ رنگِ متفاوتی بر اساس نوع پیشنهاد اضافه نشد. |
| **کیف‌پول/Wallet** | از قبل ساده (`.hp-card`/`.hp-kv-row`)؛ اکنون بدون سطحِ شیشه‌ای/گلو. |

## ۸. باگ‌های واقعیِ روشن‌شده حین این کار

چون اپ قبلاً فقط یک تمِ تیره داشت، چند سطحِ مهم پس‌زمینه‌ی خود را **هاردکد تیره** نوشته بودند در حالی که متنِ رویشان از توکنِ `--hp-text` (که اکنون بسته به تم عوض می‌شود) می‌خواند. این یعنی در تمِ روشن، متن روی رنگِ هم‌خانواده‌ی خودش می‌افتاد و ناخوانا می‌شد. همه پیدا و اصلاح شدند: **توستِ موفقیت، شیتِ پایین (کل اپ)، دیالوگِ تاییدِ حذف، هدر/کامپوزرِ چت، نوارِ ناوبریِ پایین**، به‌علاوه چند بج وضعیت (در‌انتظار/تاییدشده/ردشده، وضعیت نشستِ چت، بنرِ قطعیِ اتصال) که رنگِ متنِ روشنِ ثابت روی پس‌زمینه‌ی رنگیِ ثابت داشتند. همه به توکن‌های معنایی (`--color-surface-elevated`, `--color-success/-warning/-danger`) منتقل شدند تا در هر دو تم درست باشند.

## ۹. RTL/LTR و تلگرام مینی‌اپ

هیچ‌کدام تغییر نکردند — این بازطراحی فقط رنگ/فاصله/شعاع/سایه را عوض کرد، نه جهتِ چیدمان. اپ از قبل صرفاً با `dir="rtl"|"ltr"` روی `<html>` + خواصِ منطقیِ CSS (`inset-inline-start/end`, `text-align: start/end`) کار می‌کند (`src/i18n/config.ts`) — چیزی در این پاس دست نخورد. مقداردهیِ Telegram WebApp، auth، و فراخوانی‌های API هم دست‌نخورده باقی ماندند.

## ۱۰. آنچه عمداً حذف شد

گرادیانت‌های تزئینی (به‌جز گلاسِ سفیدِ ظریفِ روی کارتِ بانکی که هنوزهم واقعی/کارکردی است، نه رنگی)، Glow/سایه‌ی رنگی، سه پالتِ رنگیِ قابل‌سوییچ، رینگِ آواتارِ گرادیانتی، کاورِ گلوداریِ پروفایل، کارتِ شیشه‌ایِ شناور، پوششِ رنگیِ محتوای قفل‌شده، رنگ‌های وضعیتِ هاردکدشده، فایلِ مرده‌ی `src/index.css` (هرگز import نمی‌شد).
