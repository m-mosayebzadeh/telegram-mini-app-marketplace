## ۲. نقد طراحی و تجربه‌ی کاربری فعلی

### ۲.۱. مشکل ریشه‌ای: دو سیستم طراحی موازی

اپ هم‌زمان از دو سیستم استفاده می‌کند:

- کیت `telegram-ui` — ۶۴ مورد (Spinner ۲۶، Placeholder ۲۵، Input ۶، Avatar ۴، Textarea/Section/Cell ۳)
- سیستم سفارشی `hp-*` — ۲۱۵ کلاس CSS

این دو ذاتاً با هم در تضادند: کامپوننت‌های کیت تلگرام خودکار تم روشن/تاریک
تلگرام را دنبال می‌کنند، اما `hp-*` عمداً روی یک تم تاریک ثابت قفل شده است.
نتیجه این است که پرکاربردترین سطوح (loading / empty / error) با ظاهری از یک
سیستم دیگر رندر می‌شوند.

نکته: در سند فنی پروژه، دلیل انتخاب کیت تلگرام صراحتاً «هماهنگی خودکار با تم
روشن/تاریک تلگرام» ثبت شده — یعنی معماری فعلی با دلیل مستندشده‌ی خودش در تضاد
است.

### ۲.۲. تزئین به‌جای سلسله‌مراتب

۱۹ گرادیانت + ۲۵ سطح گلس + ۱۹ سایه (بخشی glow رنگی) یعنی «مهم بودن» با افکت
منتقل می‌شود، نه با موقعیت، فضا و تایپوگرافی. وقتی همه‌چیز درخشان و شیشه‌ای
است، هیچ‌چیز برجسته نیست. این همان الگویی است که یک رابط را شبیه قالب آماده
می‌کند.

### ۲.۳. نبود مقیاس

۲۰ اندازه‌ی متمایز فونت یعنی **هیچ مقیاس تایپوگرافی وجود ندارد** — هر کامپوننت
اندازه‌ی خودش را اختراع کرده است. مقادیر نیم‌پیکسلی (۱۲.۵ / ۱۳.۵ / ۱۶.۵)
نشانه‌ی قطعی این وضعیت‌اند. همین مشکل برای radius (۱۷ مقدار) و spacing نیز
برقرار است؛ هیچ شبکه‌ی ۴ یا ۸ پیکسلی در کار نیست.

### ۲.۴. ۷۴ استایل inline

هر استایل inline یعنی سیستم طراحی نیاز واقعی آن صفحه را پوشش نداده و
توسعه‌دهنده مجبور به وصله شده است. بیشترین موارد: `Activity.tsx` (۱۰)،
`AdminTopUps.tsx` (۸)، `TopUp.tsx` (۶).

### ۲.۵. ناوبری و معماری اطلاعات

- **اپ روی پروفایلِ خودِ کاربر باز می‌شود**، نه روی ویترین. برای یک مارکت‌پلیس
  این یک اشتباه استراتژیک است: اولین تب باید ارزش اصلی محصول باشد.
- **کیف پول ۵ مسیر دارد اما هیچ حضوری در ناوبری ندارد** — زیر تنظیمات پروفایل
  دفن شده است. در محصولی که هسته‌اش پول است، این یعنی پول در دسترس نیست.
- **۳۴ مسیر با ۴ الگوی هدر متفاوت** و ۴ صفحه بدون هیچ هدری. کاربر در هر صفحه
  باید دوباره یاد بگیرد کجاست و چطور برمی‌گردد.

### ۲.۶. ویترین — ضعیف‌ترین نقطه

مهم‌ترین صفحه‌ی محصول در حال حاضر یک **لیست متنی ساده** است: عنوان +
«۱۰۰ استارز · ۱۰ دقیقه». بدون عکس، بدون آواتار، بدون هویت ارائه‌دهنده، بدون
فیلتر، بدون سیگنال اعتماد.

محصول شما «خرید وقت و توجهِ یک انسان» است — یعنی **آدم‌ها محصول‌اند** — اما
ویترین هیچ آدمی نشان نمی‌دهد. هیچ دلیلی برای مرور کردن وجود ندارد.

ضمناً سند فنی (بند ۲۴۹) از قبل تصمیم گرفته بود ویترین باید مدل «آگهی
دیوارمانند با فیلتر قیمت/مدت/امتیاز» باشد، که هرگز ساخته نشد.

### ۲.۷. هدف لمسی زیر استاندارد

```
.hp-btn-sm    → padding: 7px 12px + font-size: 12.5px   ≈ ارتفاع ۳۱px
.hp-chat-back → padding: 4px 6px                        ≈ عرض ۳۴px
```

حداقل استاندارد ۴۴px در iOS و ۴۸px در اندروید است.

### ۲.۸. نقطه‌ی قوتی که باید حفظ شود

پیاده‌سازی راست‌چین درست انجام شده است: ۲۳ مورد logical property و تنها ۱ قانون
اختصاصی جهت. این یعنی راست‌چین/چپ‌چین یک پیاده‌سازی است نه دو تا. این اصل باید
در سیستم جدید نیز قانون باشد.

## ۳. مواردی که کاملاً کنار گذاشته می‌شوند

1. سیستم سه‌تمی (velvet / copper / jade) به‌همراه سوییچر تم و کانتکست تم
2. تمام گرادیانت‌ها به‌عنوان سطح یا پس‌زمینه‌ی دکمه
3. گلس‌مورفیسم به‌عنوان سطح پیش‌فرض (۲۵ مورد)
4. glowهای رنگی به‌عنوان سایه
5. توکن‌های `--hp-*` فعلی (brand-hue هستند، نه semantic)
6. استفاده‌ی مستقیم از کیت تلگرام در صفحات
7. هر ۷۴ استایل inline
8. هر ۴ الگوی هدر (به یک کامپوننت واحد با slot تبدیل می‌شود)
9. ویترین متنی فعلی
10. `--hp-gold` و منطق «محتوای پریمیوم طلایی» (رنگ نباید تنها حامل معنا باشد)

## ۴. جهت طراحی جدید (تأییدشده)

### ۴.۱. ایده‌ی مرکزی

> **محصول، آدم‌ها هستند. رابط باید ساکت بماند تا آدم‌ها دیده شوند.**

رابط خنثی، دقیق و بی‌سروصدا؛ رنگ و گرمی از عکس پروفایل‌ها و محتوای کاربران
می‌آید، نه از گرادیانت‌های رابط.

### ۴.۲. تصمیم‌های تأییدشده

| # | تصمیم |
|---|---|
| ۱ | **دقیقاً دو تم: روشن و تاریک.** اپ نباید شبیه تلگرام شود — هویت مستقل و یکتا، اما با الهام از تلگرام |
| ۲ | **Accent گرم**: بنفش یا نارنجی. حس هدف: گرم، جذاب، «hot». انتخاب نهایی پس از دیدن نمونه‌ی بصری |
| ۳ | **کیت تلگرام کاملاً کنار گذاشته می‌شود** (فقط ۷ کامپوننت در استفاده است) |
| ۴ | **ترتیب تب‌ها تغییر می‌کند** (ویترین اول) — پس از تأیید شماتیک بصری |

### ۴.۳. تغییرات ساختاری و ناوبری

| تغییر | دلیل |
|---|---|
| ویترین اولین تب شود | اولین تب = ارزش اصلی محصول |
| ویترین از صفر: کارت آدم‌محور (آواتار، نام، bio کوتاه، تگ علاقه‌مندی، قیمت، سیگنال اعتماد) | الان هیچ دلیلی برای مرور کردن وجود ندارد |
| فیلتر قیمت/مدت روی ویترین | بدون فیلتر، لیست با رشد غیرقابل‌استفاده می‌شود |
| موجودی کیف پول به‌صورت chip در هدر | پول باید ۱ تپ فاصله داشته باشد، نه ۳ تپ زیر تنظیمات |
| یک کامپوننت هدر واحد با slotهای back / title / action | ۴ الگو به ۱ الگو |
| اکشن اصلی هر صفحه، پایین و ثابت | استفاده‌ی یک‌دستی |
| فرم‌های کوتاه به bottom sheet به‌جای صفحه‌ی جدید | کاهش عمق ناوبری |
| ۴ تب + تب ادمین شرطی | بیش از ۵ تب قابل اسکن نیست |

### ۴.۴. زبان بصری

- **Radius:** ۴ پله (۸ / ۱۲ / ۱۶ / ۲۴) به‌علاوه‌ی `full` فقط برای آواتار و chip
- **سایه:** حداکثر ۲ پله، فقط برای عناصر شناور (sheet، toast). پیش‌فرض: بدون سایه
- **مرز:** hairline تک‌پله برای جداکننده‌ها
- **ساختار:** لیست و سکشن با فاصله و hairline؛ کارت فقط وقتی محتوا واقعاً یک
  «شیء» جداشدنی است. هرگز کارت داخل کارت
- **آیکون:** یک ست واحد outline با stroke ثابت (ادامه‌ی رویکرد فعلی)

### ۴.۵. تایپوگرافی

فونت Vazirmatn حفظ می‌شود (پوشش کامل فارسی و لاتین). از ۲۰ اندازه به یک مقیاس
۷ نقشی:

```
display  28/34  700
title    22/28  700
heading  18/24  600
body     15/26  400
body-md  15/26  500
label    13/18  600
caption  12/16  400
```

بدون هیچ مقدار نیم‌پیکسلی. هر اندازه‌ی جدید یعنی یک نقش جدید با دلیل مستند.

### ۵.۳. قانون حاکم

Design System **مرجع نهایی** طراحی پروژه است. اگر در آینده بین یک طراحی جدید و
این سیستم تضاد پیش آمد، ابتدا در سطح سیستم تصمیم گرفته می‌شود: یا سیستم عمداً
تغییر می‌کند و سند به‌روزرسانی می‌شود، یا طراحی تغییر می‌کند. هیچ صفحه‌ای
به‌صورت مستقل و بی‌قاعده طراحی نمی‌شود.

فایل موارد ممنوع به‌اندازه‌ی بقیه مهم است: سیستمی که فقط «بله» می‌گوید، زیر
فشار هیچ راهنمایی نمی‌دهد.

## ۶. مراحل بعدی

1. تحلیل و نقد وضعیت فعلی — **انجام شد** (همین سند)
2. **نمونه‌ی بصری**: شماتیک ناوبری و موکاپ صفحات کلیدی در دو جهت رنگی
   (بنفش / نارنجی) برای انتخاب
3. نوشتن Design System به‌عنوان سند مرجع
4. پیاده‌سازی لایه‌ی توکن و کامپوننت‌های پایه
5. مهاجرت صفحات — فاز اول: کاربر (ویترین، پروفایل، تعاملات، گفتگوها، کیف پول)؛
   فاز دوم: پنل ادمین
